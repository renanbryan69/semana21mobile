# semana21mobile


1. Como identificar as áreas que precisam de refatoração?
Eu procuraria códigos repetidos, muito complicados ou difíceis de entender. Também poderia usar ferramentas como o SonarQube para encontrar problemas no código.

2. Quais técnicas utilizar?
Eu usaria nomes mais claros para variáveis e métodos, dividiria funções muito grandes em menores e evitaria repetir o mesmo código. Também simplificaria estruturas muito complexas.

3. Por que não alterar o comportamento do código?
Porque a refatoração deve melhorar o código sem causar novos erros ou mudar o que o programa já faz. Assim, as funcionalidades continuam funcionando normalmente.

4. Como documentar as mudanças?
Eu registraria o que foi alterado, o motivo da mudança e quais partes do código foram melhoradas. Também faria testes para confirmar que tudo continua funcionando.

Plano de ação:
Primeiro identificar os problemas, depois fazer as alterações aos poucos, testar o sistema e documentar as mudanças. Dessa forma, o código fica mais organizado e fácil de manter.
